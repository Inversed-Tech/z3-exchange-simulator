# Z3 Stack Integration Notes

Integration reference for the Z3 Docker Compose stack — the primary testing target for
this project. The simulator drives Z3 through its unified RPC Router endpoint.

For a plain-English explanation of the components and their roles, see
[`docs/architecture/z3-overview.md`](../architecture/z3-overview.md).

## What the Z3 repository is

Z3 is a **Docker Compose orchestration repository** that runs Zebra, Zaino, and Zallet
as a unified stack. It is not a Rust codebase — it bundles pre-built Docker images of
each component with configuration files and startup scripts.

In regtest mode, Z3 adds an **RPC Router**: a small Rust service that exposes a single
JSON-RPC endpoint at `:8181` and transparently forwards calls to the correct backend
(Zebra at `:18232` or Zallet at `:28232`) based on the method name. The simulator
connects exclusively to this router.

---

## Services and ports

| Service | Port | Protocol | Purpose |
|---|---|---|---|
| Zebra | 18232 | JSON-RPC | Full node — chain state, block production |
| Zaino | 8137 | gRPC | LightWallet CompactTxStreamer (for light clients) |
| Zallet | 28232 | JSON-RPC | Wallet — accounts, transactions, balances |
| **RPC Router** | **8181** | **JSON-RPC** | **Unified regtest endpoint — simulator connects here** |

The simulator calls only the RPC Router (`:8181`). The router handles forwarding
internally. Direct access to Zebra or Zallet ports is not required during normal
simulator operation.

## Prerequisites

- Docker and Docker Compose (v2)
- Git

No Rust toolchain is required — the stack uses pre-built Docker images.

## Setup

```sh
# Clone Z3 at the pinned commit
git clone --branch dev https://github.com/ZcashFoundation/z3 external/z3
cd external/z3
git checkout <pinned-commit>   # see z3-commits.lock

# One-time regtest initialization (generates wallet keys, RPC auth, mines genesis block)
./scripts/regtest-init.sh

# Start the regtest stack
docker compose --env-file .env.regtest up -d
```

The init script only needs to run once per fresh clone. It sets up the wallet password
hash, configures RPC authentication (username/password for regtest), starts Zebra, and
mines the first block.

---

## Connecting to the RPC Router

The simulator's RPC client connects to the unified endpoint:

```
http://127.0.0.1:8181
```

Authentication uses the username/password set during regtest init (stored in `.env.regtest`
after the init script runs).

Example call:

```sh
curl -u user:password -d '{"method":"getblockchaininfo","params":[],"id":1}' \
  http://127.0.0.1:8181
```

---

## Shutdown

```sh
docker compose --env-file .env.regtest down
```

Add `-v` to also remove volumes (resets chain state).

---

## Log capture

The simulator captures Docker logs from each service:

```sh
docker compose --env-file .env.regtest logs -f zebra   # stream Zebra logs
docker compose --env-file .env.regtest logs -f zallet  # stream Zallet logs
docker compose --env-file .env.regtest logs -f zaino   # stream Zaino logs
```

In the simulator process harness (T2), logs are captured programmatically via the Docker
API or by running `docker compose logs` as a child process and piping its output to the
run's `component_logs/` directory.

---

## Health check

The simulator considers the stack ready when the RPC Router returns a successful
response to `getblockchaininfo`. Poll this endpoint after `docker compose up` until it
responds before starting a scenario run.

---

## Configuration

Z3 manages its own configuration files under `config/regtest/` in the Z3 repository:
- `config/regtest/zallet.toml` — Zallet config for regtest
- `config/regtest/zaino.toml` — Zaino config for regtest

The simulator does not need to write config files for the Z3 components. All config is
owned by the Z3 repo.
