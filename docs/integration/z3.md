## What the Z3 repository is

Z3 is a **Docker Compose orchestration repository** that runs Zebra, Zaino, and Zallet
as a unified stack. It is not a Rust codebase — it bundles pre-built Docker images of
each component with per-network configuration.

In regtest mode, Z3 adds an **RPC Router**: a small Rust service that exposes a single
JSON-RPC endpoint at `:8181` and transparently forwards calls to the correct backend
(Zebra or Zallet) based on the method name. The simulator connects exclusively to this
router. The router is **regtest-only** — mainnet and testnet have no router and use
cookie auth on the individual component ports.

---

## The contract: `z3-contract.yaml`

Z3 ships a canonical machine-readable inventory at `z3-contract.yaml` (validated by a
JSON schema, `z3-contract.schema.json`) listing every network's ports, service DNS
names, auth mode, volumes, and healthchecks. **The simulator reads this file rather than
hardcoding any of these values** — see `src/z3/contract.rs` and
[`Z3Config::from_contract`](../../src/z3/mod.rs). The port table below is derived from the
contract and is reproduced here only for orientation; the contract is the source of truth.

See the Z3 repo's `docs/contract.md`, `docs/regtest.md`, `docs/integrations/`, and
[`docs/faq.md`](https://github.com/ZcashFoundation/z3/blob/main/docs/faq.md).

## Services and regtest host ports

| Service | Regtest host port | Protocol | Purpose |
|---|---|---|---|
| Zebra RPC | 29232 | JSON-RPC | Full node — chain state, block production |
| Zebra health | 28080 | HTTP | `/healthy` (liveness) and `/ready` (readiness) |
| Zaino gRPC | 28137 | gRPC (h2c) | LightWallet CompactTxStreamer (light clients) |
| Zaino JSON-RPC | 28237 | JSON-RPC | zcashd-style mirror — directly callable (see [zaino.md](zaino.md)) |
| Zallet RPC | 50232 | JSON-RPC | Wallet — accounts, transactions, balances |
| **RPC Router** | **8181** | **JSON-RPC** | **Unified regtest endpoint — simulator connects here** |

Host ports differ from the in-container ports (e.g. Zebra serves `18232` inside the
network, published on host `29232`); networks use distinct host ports so mainnet,
testnet, and regtest can run side by side. The simulator only needs the RPC Router
(`:8181`); the router forwards to Zebra/Zallet internally.

## Per-network Compose projects

Each network runs as its own Compose project, set via `COMPOSE_PROJECT_NAME` in the
corresponding env file (`.env.regtest` → `z3-regtest`). This isolates stacks so several
networks can run concurrently. The simulator scopes its `docker stats` resource sampling
to the active project's containers (`<project>-<service>-N`).

---

## Authentication

In regtest the RPC Router requires **HTTP Basic Auth**. The credentials come from the
contract's `rpc_auth.credential_env_vars` (`Z3_REGTEST_RPC_ROUTER_USER` /
`Z3_REGTEST_RPC_ROUTER_PASSWORD`), defaulting to **`zebra` / `zebra`**. Zebra's own
cookie auth is disabled in regtest; the router handles auth. The simulator's RPC client
sends these credentials on every call ([`RpcClient::with_basic_auth`](../../src/rpc/mod.rs)).

Mainnet and testnet have no router and use cookie auth on the component ports instead.

## Prerequisites

- Docker and Docker Compose (v2)
- Git

## Setup

```sh
# Clone Z3 at the pinned commit (see z3-commits.lock); `make clone-z3` does this.
git clone --branch main https://github.com/ZcashFoundation/z3 external/z3
cd external/z3
git checkout dfb9d0eae6d3f67a3c184e0d8fcb1166e7740724

# One-time regtest initialization (wallet keys, RPC auth, genesis).
./scripts/regtest-init.sh

# Start the regtest stack (project: z3-regtest).
docker compose --env-file .env.regtest up -d
```

The `.env.regtest` file sets `COMPOSE_PROJECT_NAME=z3-regtest` and loads the regtest
overlay, so this single command brings up the isolated regtest project.

## Connecting to the RPC Router

```
http://127.0.0.1:8181
```

Example call (note Basic Auth):

```sh
curl -u zebra:zebra -d '{"method":"getblockchaininfo","params":[],"id":1}' \
  http://127.0.0.1:8181
```

---

## Shutdown

```sh
docker compose --env-file .env.regtest down
```

Add `-v` to also remove volumes (resets chain state).

---

## Log capture

The simulator captures Docker logs from each service into the run's `component_logs/`
directory by running `docker compose logs` as a child process:

```sh
docker compose --env-file .env.regtest logs -f zebra
docker compose --env-file .env.regtest logs -f zallet
docker compose --env-file .env.regtest logs -f zaino
```

## Health check

Two options, both contract-described:

- **Router**: the simulator considers the stack ready when the RPC Router returns a
  successful `getblockchaininfo` (with Basic Auth) reporting `"chain": "regtest"`.
- **Zebra health endpoint**: HTTP `/ready` on host port `28080` (readiness — synced to
  tip) and `/healthy` (liveness). Zallet has no healthcheck (distroless image); wait for
  Zebra's `/ready` and assume Zallet follows shortly after.

---

## Configuration

Z3 owns all component configuration under its per-network config directory
(`Z3_CONFIG_DIR`, e.g. `config/regtest/` with `zallet.toml`, `zaino.toml`). The simulator
does not write Z3 component config.

---

## Monitoring profile (optional)

Z3 bundles an opt-in `monitoring` Compose profile (Prometheus, Grafana, Jaeger with
spanmetrics, AlertManager). When enabled it exposes per-RPC latency and resource
profiles server-side. The simulator can cross-validate its own client-side metrics
against this profile — see [`docs/architecture/observability.md`](../architecture/observability.md).
